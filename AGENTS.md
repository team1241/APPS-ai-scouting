# GitHub issues and pull requests

These instructions apply only to `team1241/APPS-ai-scouting`. Use GitHub issue numbers in place of the default Linear ticket convention for this repository.

- Before creating a branch or pull request, identify the GitHub issue for the work and verify it belongs to this repository. If no issue exists, create one when issue creation is authorized; otherwise ask the user for the issue number.
- Start every new branch name with `GH-<issue-number>`, for example `GH-42-event-configuration`.
- Start every new pull request title with the same prefix, for example `GH-42: Add event configuration`.
- Include `Closes #<issue-number>` in the pull request description when merging completes the issue; use `Refs #<issue-number>` for partial work.
- Before opening the pull request, verify its head branch and title use the matching issue prefix.
